# 迴響演練室 · ECHO / RAID LAB

公開網站：[cif0219.github.io/ffxiv_planner](https://cif0219.github.io/ffxiv_planner/) · 原始碼：[cif0219/ffxiv_planner](https://github.com/cif0219/ffxiv_planner)

從 [ffxivtesthub/p8s-concept](https://github.com/ffxivtesthub/p8s-concept) 延伸的 FFXIV 副本攻略與互動走位練習入口。零建置、零 npm 套件依賴、繁體中文，保留原版概念支配 I 的引擎、素材與獨立專練頁。

## 本機啟動

需要 Node.js 24（與 CI 一致）。在專案目錄執行：

```sh
npm start
```

開啟 http://127.0.0.1:4173 。入口為 `dist/index.html`；P8S 使用 `#/raids/p8s`，不需要伺服器端路由，直接支援 GitHub Pages 子目錄部署。原版專練位於 `high-concept.html`。

```sh
npm test
npm run check
```

- P8S 前後半 16 章節：開場、蛇 I、獸 I、萬象之火、四重火炎、蛇 II、獸 II、前半轉場、自然支配 I、概念支配 I、萬象灰燼、自然支配 II、概念支配 II、兩次支配者之塔與終局。
- 蛇先／獸先分支；八個可選隊伍位置；單章或連續流程；手動引導、限時挑戰、自動示範；0.5–2 倍速度、暫停與本步重試。
- WASD／方向鍵或觸控點擊移動；Q／E 或八方向按鈕轉向；分攤人數、散開重疊、指定角色踩塔、蛇眼朝向、紫圈隔離、火冰遠近誘導、擊退落點與兩秒合成判定。
- 攻略、當前機制、個人任務與隊伍狀態一起更新。概念支配 I 直接重用原版 `engine.mjs`，顯示遊戲狀態圖示與拼圖。
- 通過章節全部步驟才記錄完成；示範與跳步不算章節通過。統計、角色與上次章節只存在本機 localStorage，封鎖儲存時仍可使用。
- 分享網址保存章節、角色、變身順序與隨機種子，重新載入可重現同一組配置。切換視窗或隱藏分頁會自動暫停。

## 模擬精度與資料來源

此版本是覆蓋全副本主要機制的**分段教學模擬**，並非遊戲戰鬥系統或逐幀還原。實戰參考事件時間依 [Cactbot P8S 時間軸](https://github.com/quisquous/cactbot/blob/main/ui/raidboss/data/06-ew/raid/p8s.txt) 整理；前後半各自計時，前半依不同變身分支換算。畫面中的教學倒數獨立於實戰時間，包含移動和觀察時間。

機制交叉參考 [P8S 機制資料](https://ffxiv.consolegameswiki.com/wiki/P8S)，概念支配 I 保留原專案的[菓子攻略](https://www.bilibili.com/video/BV1q3411Q7jg/)配置。狀態圖示來源與版權見 `dist/assets/status/README.md`。

目前簡化：地火呈現結算格；蛇的分工、獸 II 路徑與概念 II 牽線使用教學配置；概念 II 是帶預設合成狀態的分段檢查點，尚未完整重現所有塔色與分身隨機排列。範圍與移速為教學值。不計算傷害、治療、減傷、仇恨、輸出循環、擊殺門檻或網路延遲；終局通過代表完成走位演練。不同隊伍與攻略的站位可能不同。

## 驗證

`npm test` 包含保留的概念支配 I 測試與新副本引擎測試：兩種分支 × 40 組種子的建議解法、漏塔／重疊／錯誤朝向／擊退死亡、合成中斷與鎖定，以及兩種分支 × 12 組種子的完整連續自動走位。CI 先執行語法檢查與測試再部署 `dist/`。

## 原版概念支配 I 說明

零建置靜態網頁，繁體中文、單人走位。其餘七名隊員自動操作。

執行 `node server.mjs`，開啟 http://127.0.0.1:4173 。執行 `node --test tests/engine.test.mjs` 驗證機制引擎。

## GitHub Pages 部署

此專案已附 `.github/workflows/pages.yml`。建立 GitHub 儲存庫並將本專案的 `main` 分支推送上去後，到儲存庫 **Settings → Pages → Build and deployment → Source** 選擇 **GitHub Actions**。其後每次推送 `main`，便會自動將 `dist/` 裡的靜態網站發佈到 `https://<帳號>.github.io/<儲存庫名稱>/`。GitHub Free 使用 Pages 時，儲存庫需設為公開。部署網站的入口為 `dist/index.html`，不需要執行建置指令。

- 09:00–09:35：短 α 左上 A、短 β 左下 B、短 γ 右下 C；右上 2 點二人分攤＋長 α；中央三人分攤＋長 β／γ。
- 約 09:40–10:10：依首輪塔色合成兩個短概念，依 A/B/C 優先度分北南塔，躲半場攻擊。
- 10:20–11:20：長 α／β／γ 去 A/B/C 外側，未合成短概念在相同角落內側；二人／三人分攤者補入已合成概念位置。首次合成的兩人則在右上 2 點附近分散待機，避開長概念爆發。
- 11:00 畫面口訣：風塔「二 A、三 B、留 C」；水塔「二 A、三 C、留 B」；雷塔「二 B、三 C、留 A」。
- 約 11:40：內側複製組「上面合成」；外側長概念組「下面合成」。前組北兩塔、後組南兩塔，每組依 A/B/C 優先度分塔。

## 模擬邊界

六步教學拆解。分段倒數、移動速度及判定半徑為教學近似值，非遊戲原始時間軸。未模擬治療、傷害、網路延遲及技能施放。合成需持續接近兩秒，錯誤合成會失敗。爆發、分攤、複製、塔與半場均依角色實際位置判定。統計僅存本機 localStorage，無後端或帳號系統。

`dist/` 可獨立託管，使用 Google Fonts（無網路時自動使用系統字型）。不包含原影片或擷取畫面。

第一輪合成與第二輪合成時，地上塔圈就會以醒目的雙層圓環顯示風／水／雷。玩家先看塔圈再比對頭上拼圖的共同圖塊；合成速查與攻略筆記都提供完整圖樣配對，α／β／γ 只作為攻略術語。完整概念會在角色頭上顯示與影片排列一致的三元素六角拼圖，金框標示主元素，風／水／雷交集對應合成結果。頭上拼圖在關閉提示後仍會顯示；引導模式會突出本輪塔的共同元素。個人面板另外提供較大的拼圖預覽。

場地底部提供技能讀條、剩餘秒數及兩秒合成連結進度。引導模式的教學讀條到零後停住等待手動結算；限時挑戰與自動示範讀完自動結算。暫停時所有讀條停止。



## 遊戲狀態圖標與倒數

頭上與個人狀態面板使用 FF14 原始 Status 圖標，合成後以動物圖標取代動物名稱；圖檔存於 `dist/assets/status/`，無須在演練中連線取得。圖標資料來自 XIVAPI 遊戲資料（Status 3330–3335、3337–3339、3346–3347），圖像版權屬 SQUARE ENIX。

依菓子影片 07:30，短概念／二人與三人分攤從 8 秒倒數，長概念從 26 秒倒數。同種長短概念使用同一原始圖標，以秒數區分；剩餘 5 秒提醒變色。長概念跨段保留剩餘時間，長爆發段為 6 秒。暫停與失敗凍結時鐘；跳段／重練復原對應檢查點的剩餘時間。引導模式每段讀條到零後停表等待手動結算；限時及示範模式連續推進。完整拼圖與動物狀態不顯示虛構到期時間。

四段連續流程保留階段選單、上一段／下一段、重練本段及只練本段；兩個踩塔專練檢查點已預先合成，保留原分配與塔色。
